# Проверки и приёмка

## Выполнено 08.09.2026

Среда: Linux x64, Python 3.12.13. UI запускался через Qt offscreen, с реальными PySide6 widgets; скриншоты в `docs/` получены из приложения. Примеры встреч на них — **демонстрационные данные**, не результат автоматического протоколирования настоящей встречи.

Результат: **22 автоматических теста пройдены**, `ruff check` и компиляция модулей успешны. Основные версии среды проверки: PySide6 6.11.2, faster-whisper 1.2.1, CTranslate2 4.8.2, NumPy 2.3.5, SciPy 1.17.0, Pydantic 2.13.4, psutil 7.2.2. Это сведения о проверке, а не Windows lock-файл.

Проверены:

- Русский поиск по префиксам и точной фразе, безопасное экранирование FTS.
- Обновление индекса после редактирования и сохранение оригинала/истории.
- Атомарное завершение аудиофрагмента, идемпотентный повтор.
- Проверка ссылок на реплики и дословного вхождения цитат.
- Версии протоколов, исключение дублей задач и сохранение пользовательского статуса.
- Напоминания в разных часовых поясах, отсутствие уведомлений для черновиков/завершённых задач, сохранение после перезапуска.
- Анализ всех частей длинного диалога; отсутствие частичного результата при сбое.
- Замены терминов с границами слов, без каскадного изменения текста.
- Ограничение локальных моделей/маршрутов LLM; HTML-экранирование и связи карты с первоисточником.
- SQLite backup с учётом WAL.
- Передискретизация stereo 48 kHz → mono 16 kHz; восстановление служебного файла записи.
- Сохранение последнего короткого WAV при остановке записи с имитированным аудиоустройством.
- Основной UI-путь: встреча → расшифровка → протокол → поиск → карта → исходная реплика, редактор напоминания.

Отдельно выполнено **реальное распознавание** 11-секундного английского аудио из тестов [Whisper](https://github.com/openai/whisper/tree/main/tests) моделью `Systran/faster-whisper-tiny` в CPU/int8. Перед загрузкой модели и inference включён offline-режим, `socket.socket.connect` заменён на запрет соединений. Получен непустой ожидаемый текст; весь вызов с загрузкой модели занял около 0,89 секунды в этой среде. Это smoke-проверка локального двигателя, **не бенчмарк Windows, русского языка, длинных встреч или двух дорожек**. Тестовое аудио и модель в проект не включены.

## Не проверено в этой среде

- Физический микрофон и настоящий WASAPI loopback на Windows, Bluetooth/USB-гарнитуры, отключение устройств.
- Реальная генерация Qwen3 через Ollama: проверены схема/контракт и контроль ошибок, но локальный сервер Ollama здесь не запускался.
- Сборка PyInstaller и запуск EXE на чистой Windows; `.github/workflows/windows.yml` подготовлен для этой проверки.
- CUDA/cuDNN, экономия батареи, работа после сна Windows, точность русской речи и разделение участников.
- Доставка уведомлений при Windows Focus Assist / «Не беспокоить»; успешная отправка в системный трей не гарантирует, что Windows покажет баннер.

## Приёмка на Windows

1. Установка в чистое окружение Python 3.12 x64; старт без моделей, информативное сообщение при попытке распознавания.
2. Подготовка модели, отключение интернета, 5-минутная запись микрофона и проверка сохранённого WAV.
3. Два источника: 10 минут звонка в наушниках, отдельные шкалы/метки источников и непустая расшифровка обеих дорожек.
4. Остановка в середине 10-секундного окна: последние слова сохранены в WAV и обработаны.
5. Уменьшение производительности: очередь растёт на диске и обрабатывается после остановки. Потеря/переполнение устройства явно сообщается.
6. Завершение приложения, повторный запуск: все встречи/задачи доступны; незавершённые зарегистрированные фрагменты остаются в очереди.
7. Ollama с заранее скачанной Qwen3 при отключённой сети: протокол покрывает все части, каждый вывод связан с цитатой.
8. Исправление расшифровки: поиск обновляется, протокол и карта помечают устаревшие сведения.
9. Напоминание через 2 минуты, работа в трее, затем проверка пропущенного напоминания после перезапуска.
10. Скриншот нужного монитора, подпись, HTML-инструкция открывается без сети с изображениями.
11. Backup/restore в другую пустую папку: текст, аудио, изображения и задачи доступны, ссылки переназначены.
12. 60-минутная встреча: измерить максимальные RAM/VRAM, RTF, отставание очереди и рост диска.

## Ограничения 0.2

- Веса не дообучаются автоматически; адаптация реализована через явный словарь и историю исправлений.
- Диаризации людей и эхоподавления нет; метки обозначают источники.
- Фрагменты речи не перекрываются, поэтому возможны обрывы слов/контекста на границах.
- Импорт поддерживает текст и 16-bit PCM WAV; MP3/MP4, потоковый импорт и импорт очень больших файлов в фоновом режиме — следующий этап.
- Напоминания требуют работающего приложения; запуск по расписанию ОС и автозапуск после входа не настроены.
- Наличие точной цитаты не исключает неверной интерпретации моделью. Протоколы требуют проверки.
- Скриншоты добавляются с подписями вручную. OCR, vision-анализ, автоматическое сопоставление снимка со сгенерированным шагом и запись действий мыши пока отсутствуют.
- Поиск текстовый; семантический поиск, RAG-ответы и слияние синонимичных тем запланированы.
- WAV не сжимается; полного UI-управления архивом и шифрования БД нет.
- Версии зависимостей ограничены диапазонами; полный Windows lock-файл следует зафиксировать после успешной сборки/приёмки.

## Исправление установки через CMD

Добавлены файлы для установки, подготовки речи/протоколов и запуска двойным щелчком. Пять дополнительных регрессионных тестов проверяют раздельный вызов двух Python launcher-путей, пути с пробелами, переход с неподдерживаемого Python на поддерживаемый, сохранение повреждённого окружения и правильную диагностику ошибки venv. Логика проверена на Linux с имитацией Windows-путей; сами CMD-файлы, реестр и двойной щелчок на Windows в этой среде не запускались.

## Проверка 0.2

Добавлены регрессионные проверки сроков очистки аудио, повторного запуска, защиты чужих файлов и необработанной очереди; сохранения/переноса/поиска заметок и редактирования/каскадного удаления связей; удаления сгенерированных задач без повторного появления; переноса напоминаний; обновлений с проверкой контрольных сумм, путей Windows и откатом при ошибке зависимостей.

Встроенный GGUF-движок проверяется отдельно от Ollama. Наличие адаптера и тестов контракта не означает, что качество реальной модели на вашем ПК уже подтверждено. Windows-установку optional wheel, WASAPI, окно напоминаний поверх других приложений и обновление после выхода из GUI нужно проверить на Windows. EXE не получает встроенный движок автоматически, если пакет llama-cpp-python не был включён при сборке.

Локальный результат 0.2: **43 теста прошли**, `ruff check .` без ошибок. Интерфейс и диалоги проверены в Qt offscreen на Linux. Встроенная генерация проверена имитацией контракта движка, без загрузки весов GGUF; качество реальных ответов не измерялось.
